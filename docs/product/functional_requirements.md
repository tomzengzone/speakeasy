# 功能需求目录

## 文档状态

- Artifact ID: `FUNCTIONAL_REQUIREMENT_CATALOG`
- Status: candidate

本目录只保存 Product Manager 决定从已批准 Vertical Slice 表达为 Functional Requirement 的当前产品行为。每行 FR 是一个可以独立审批、独立变更且独立验证的规范性需求单元，只能通过 `source_vs_ids` 直接引用一个或多个 approved VS。Stage、Increment、Work Package、PR、实现和执行结果不属于本目录。

目录条目只登记经 Product Manager 批准需要表达为 Functional Requirement 的当前产品事实。

| ID | Status | source_vs_ids | Requirement |
| --- | --- | --- | --- |
| `FR-TRAIN-001` | `approved` | `VS-TRAIN-001-1` | 学习者完成当前官方场景的一轮语音练习并触发结束动作后，系统必须展示本轮练习总结和可见的后续学习入口；练习结果失败或不可用时，系统必须展示可恢复的错误或空状态，不得错误推进学习进度。 |
| `FR-CONTENT-001` | `approved` | `VS-CONTENT-001-1` | 内容资产入口中“全部”场景主题集合必须恰好包含全部已发布且对当前学习者可见的官方场景主题；选中主题后的课程摘要集合必须恰好包含该主题下全部已发布且对当前学习者可见的课程，不得有意遗漏任一符合条件的主题或课程；每条课程摘要必须包含非空英文标题、非空中文简介与唯一一个适用等级。本范围的场景与课程等级只允许 `A1`、`A2`、`B1`、`B2`、`C1`、`C2`；每个等级字段、单个课程以及单个场景等级记录或内容轨道只能取其中一个 CEFR 值，场景主题本身可包含零个或多个不同 CEFR 的课程或内容轨道。已发布且对当前学习者可见的主题即使没有可见课程也必须保留在主题集合中，其课程集合必须显示真实空状态；获取失败不得显示为真实空状态，必须保留已知浏览上下文并提供恢复路径。`L1`、`L2`、`L3` 均为非法值并必须被拒绝，运行期不得将其作为别名、fallback 解释或并行写入值。 |
| `FR-CONTENT-002` | `approved` | `VS-CONTENT-002-1` | 一门已发布课程必须具有非空英文标题、非空中文简介、唯一一个合法 CEFR 适用等级，以及大于零且携带时间单位的典型完成时长；学习者从课程卡片或任何其他课程入口打开同一课程时，必须解析为同一已发布课程及同一版本，并展示该版本的上述信息。课程的合法 CEFR 适用等级只能是 `A1`、`A2`、`B1`、`B2`、`C1`、`C2` 之一；`L1`、`L2`、`L3` 均为非法值并必须被拒绝，运行期不得将其作为别名、fallback 解释或并行写入值。背景图为可选信息；背景图缺失不得阻止课程被打开，也不得阻止其他必备信息展示。任一入口无法解析到同一已发布课程及版本时，不得以其他课程或其他版本的基本信息替代。 |
| `FR-ACC-001` | `approved` | `VS-ACC-009-1` | 只有无法正常登录、主动选择账号恢复，并通过账号已绑定且仍可使用的手机号完成有效的一次性验证码身份验证的学习者，才符合恢复资格；验证成功时，系统必须将该手机号已绑定的既有账号确认为唯一恢复目标，已用于完成本次验证的验证码不得再次用于恢复。 |

| `FR-ACC-003` | `approved` | `VS-ACC-009-1` | 账号不存在、手机号未绑定或不可用、验证码发送失败、验证失败、验证码过期，或恢复流程在成功前中断时，本次恢复必须整体失败；系统不得因本次尝试创建新账号、改变任何身份凭据或改变任何会话，并必须允许学习者重新尝试账号恢复。 |

## 维护规则

- Product Manager 按 implementing VS 决定是否创建 FR；零条 FR 不会仅因缺少 FR 而阻止交付。
- FR 存在时必须使用固定四列表格，每行保持 approved 状态、非空 `source_vs_ids` 与非空、可测试的 `Requirement`；该产品事实不得在 TC 或 Contract 中重新定义。
- FR 变化由 Product Manager 批准；需求开发者按 `FUNCTIONAL_REQUIREMENT_CATALOG` Artifact contract 贡献内容。
