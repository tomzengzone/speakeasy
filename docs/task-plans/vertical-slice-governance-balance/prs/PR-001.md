# PR-001: 重建 Story Map 的 VS 定义与就绪规则

## Objective

重建 `story-map-develop` 的统一 Child Vertical Slice 定义、拆分判断和就绪标准，在一个自洽方法单元中平衡全部判定维度。

## Included Scope

- 在 `SKILL.md` 中更新 Overview、Process、Red Flags 和 Verification 的 VS 方法表述。
- 在 `ready-gates.md` 中建立统一定义、均衡判定维度、拆分/合并规则、就绪检查和正反例。
- 明确自然业务前置关系、相对独立性、迭代规模、端到端结果和用户交互的综合判断。

## Excluded Scope

不修改 Governance Contract、`screen-spec-generate`、Story Map 正文、现有 Story/VS、Agent、Gate、Workflow、验证器或应用代码。

## Allowed Paths

- `.agents/skills/story-map-develop/SKILL.md`
- `.agents/skills/story-map-develop/references/ready-gates.md`

## Acceptance Criteria

- 定义不是 UI 特例补丁，而是覆盖用户与情境、触发/选择、增量结果、可观察价值、相对独立性、端到端完整性、可交付性、规模、聚焦性、可验证性、恢复边界和事实分层的统一模型。
- 不再把自然业务前置关系直接判为 sibling 无效，也不允许以端到端为由合并多个可分别交付结果。
- 用户交互可以作为产品行为；纯技术任务和纯视觉参数仍不构成 VS。
- 失败/恢复只在形成独立用户决策或结果时拆分，否则跟随所属结果。
- Skill 主文保持精简，可选细节只存在于其直接 reference，不复制 Contract 权威事实。

## Changes Made

- 在 `story-map-develop/SKILL.md` 中用相对独立性、聚焦增量结果、端到端交付边界和可观察价值替换绝对 sibling 无依赖规则。
- 在直接 reference 中建立 12 个均衡判定维度、拆分/合并信号、就绪检查、事实分层和正反例。
- 明确自然业务前置关系不否定 VS 独立性，也不强制合并；同时禁止用“端到端”名义合并多个可分别交付结果。
- 用是否形成新能力、选择、控制权或可观察结果判定用户交互与恢复路径；纯布局、视觉参数、组件选型和内部实现仍排除。
