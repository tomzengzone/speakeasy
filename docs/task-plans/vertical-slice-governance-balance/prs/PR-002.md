# PR-002: 对齐 Story Map 与 Screen Spec 权威边界

## Objective

对齐 `STORY_MAP` 与 `SCREEN_SPEC` 的权威职责，使产品交互语义和具体界面化表达有清晰、单向的事实流。

## Included Scope

- 精化 `STORY_MAP` 与 `SCREEN_SPEC` Artifact applicability，明确各自语义范围。
- 更新 `screen-spec-generate`，要求细化 approved VS 而不得重新定义、缩减或发明产品行为。
- 保持 `SCREEN_SPEC` 继续以 `STORY_MAP` 为 required direct input。
- 修正 Story/Slice cutover validator 的 current-lineage 语义识别，使其接受当前状态标题而不强制保留历史 PR 编号，并补充回归测试。

## Excluded Scope

不修改 Story Map 文档、现有 Story/VS、Screen Spec 内容、FR/TC、Agent、Gate、Workflow、API/AI Contract、其他 validator 或应用代码。

## Allowed Paths

- `docs/process/governance/artifacts/product.json`
- `docs/process/governance/artifacts/engineering.json`
- `.agents/skills/screen-spec-generate/SKILL.md`
- `scripts/validate_story_slice_cutover.py`
- `tests/test_validate_story_slice_cutover.py`

## Acceptance Criteria

- `STORY_MAP` 明确拥有用户目标、行为/选择、产品状态影响、可见结果和关键恢复语义。
- `SCREEN_SPEC` 明确拥有 approved VS 的页面结构、组件呈现、精确状态转换、视觉反馈、无障碍和 selector 等实现就绪 UX 事实。
- 两个 Artifact 不重复拥有同一事实，`screen-spec-generate` 不发明产品行为。
- Contract 与 Skill 表述精简，不复制 path、owner、lifecycle 或 Gate 规则。
- Cutover validator 可识别带可选历史 PR 前缀的 `current lineage` 当前状态标题，仍拒绝缺失或旧 lineage；仓库 cutover 校验与其回归测试均通过。

## Changes Made

- 精化 `STORY_MAP` 与 `SCREEN_SPEC` applicability，分别持有产品语义和实现就绪 UX 事实，并保持 `SCREEN_SPEC.required_direct_inputs` 为 `STORY_MAP`。

- 增加回归覆盖：无 PR 前缀的当前 lineage heading 通过；旧 heading 即使正文普通提及 `current lineage` 仍失败。
