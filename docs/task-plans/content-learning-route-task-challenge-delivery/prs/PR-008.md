# PR-008: Backend Course 启动与 AI opener

## Objective

在现有 Practice start/resume、AI Gateway、usage/provider adapters 和 message persistence 上增加 exact Course launch 与一次性 opener，
保持 legacy 请求兼容并确保 provider/schema failure 走确定性 fallback。

## Included Scope

- 新增 `V202608110002__practice_session_opener.sql`，只增加单 opener 持久化/唯一性所需 schema、constraint/index。
- 扩展 PracticeController/PracticeService 的 one-of validation、exact binding resolution、course session create/resume 和 response `course_context`。
- 恢复只匹配当前 user + CourseVersion + binding；不恢复 legacy 或其他 Course session。
- 在现有 AiGatewayService/AiProviderGateway/DashScope/deterministic adapter 中增加 opener candidate 调用与校验。
- 首次新建时生成并持久化一条 coach opener；resume 不重复调用；provider/schema failure 使用 deterministic fallback。
- 增加四个定向测试，覆盖 launch、isolation/recovery、gateway/schema 和 fallback/no-repeat。

## Excluded Scope

- learning route、audio proxy、Flutter、新 provider、录音/submit turn/multiturn 或重复 message/session store。
- 重跑 PR-007 migration tests 或修改第一条 migration。

## Acceptance Criteria

- legacy tuple 与 `course_launch` 恰好一组；混合或不完整输入为 422，legacy behavior 保持不变。
- server 解析 exact published/visible version 与 frozen binding，忽略/拒绝客户端替代 scenario/level 的尝试。
- exact course resume isolation 可证明；并发或重复启动不会产生两个活动 session 或两个 opener。
- 合法 opener ≤240、英文且无禁止字段；invalid/timeout 使用指定 fallback，session 仍成功。
- response `course_context` 对 legacy 为 null、对 course session 为 exact identity/title/CEFR；历史 opener/message 顺序稳定。
