# PR-001: 产品批准、FR 与测试意图

## Objective

使用 `story-map-develop` 对 draft `US-CONTENT-003/004` 及其 Child VS 做就绪审查、必要的最小改写和产品批准，
再用 `requirement-refine` 与 `test-case-generate` 固化可测试 FR、FR-TC 和四条 VS-TC，建立后续工程工作的唯一产品 authority。

## Included Scope

- 审查并批准 003/004，明确固定五阶段、仅 01 可进入、02–05 的真实未交付状态。
- 明确 004 只含课程主题/CEFR、条件性历史消息、历史语音回放、AI 开场与返回路线；不含录音、提交新作答或多轮对话。
- 建立 `FR-CONTENT-003`、`FR-CONTENT-004`，覆盖路线状态/下一动作、exact Course launch/context、历史消息/音频、opener/fallback。
- 建立对应 FR-TC，以及四条 VS-TC：路线正常/未知降级、挑战 exact context/history、opener/fallback、音频回放/安全失败。
- 重建直接 lineage 与 `docs/quality/traceability.md` 派生投影。

## Excluded Scope

- 架构、领域、API/OpenAPI、Prompt、UX、migration、Backend 或 Flutter 实现。
- 批准或实现 US-CONTENT-005、007–012；虚构生产 Course inventory。

## Allowed Paths

- `docs/product/story_map.md`
- `docs/product/functional_requirements.md`
- `docs/quality/test_cases.md`
- `docs/quality/traceability.md`
- `docs/task-plans/content-learning-route-task-challenge-delivery/**`，仅计划状态、checkpoint 与证据

## Context Budget

- 上限：18k tokens。
- 读取范围：003/004 Story/VS、适用 Story ready gate、现有 001/002 FR/TC 表达范式、架构矩阵对应两行和 traceability schema。
- 若审批需拆分超过两个 FR 或四条 VS-TC，先修订本卡并说明拆分理由，不在执行中扩写。

## Acceptance Criteria

- Story/VS 状态与 Product Manager 审批证据一致，AC 明确五阶段真实可用性、conditional history/audio、fallback 和“不含新作答”。
- FR/TC 有稳定 ID、Given/When/Then、failure/recovery 和直接 lineage；Task Plan 文本未被当作产品事实源。
- 004-1 不再承诺进入后即可看到不存在的 learner 历史；无历史时仍能显示 AI opener 并准备开始。
- TRACEABILITY 无 orphan、重复直接边或越权映射。
