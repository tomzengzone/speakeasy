# PR-009: Backend 历史语音安全回放

## Objective

在现有 Media Storage adapter 上增加 owner-checked validated audio read，通过 Practice session/message scoped endpoint 代理音频字节，
统一 privacy-safe failure，并证明 local/OSS adapter 均不泄漏内部 locator。

## Included Scope

- 为 `AiMediaStorageService` 增加最小 authenticated read abstraction，复用现有 asset repository、retention 与 validation facts。
- Practice 校验 current user/session/message 关系；Media 校验 asset validated、未删除、未过期且为 audio。
- 实现 `/practice/sessions/{session_id}/messages/{message_id}/audio`，返回 `audio/*` 与 `Cache-Control: private, no-store`。
- local/OSS adapter 返回 bytes/stream，不向 controller 暴露 object key、signed URL 或 provider read URL。
- cross-user、wrong session、no audio、deleted/expired 收敛为 404；storage unavailable 为 503。
- 增加两个 endpoint/security 测试并扩展现有 `AiMediaStorageServiceTest`。

## Excluded Scope

- 数据库 migration、新 media store、公开 URL、上传/录音/转写、route/opener 或 Flutter playback。
- 改变既有 asset retention/deletion 事实或把 Practice 变成 Media owner。

## Acceptance Criteria

- authorization 顺序不会泄漏 session/message/asset 是否存在；所有 privacy cases 返回相同外部 404 envelope。
- 仅 validated、未删除、未过期的 audio asset 可读取；storage dependency failure 明确为 503。
- 响应 content type 来自验证后的 audio metadata，cache 为 private/no-store，body 不含 locator、URL 或 provider 信息。
- local 与 OSS adapter 都满足同一 read contract；无 DB 变更。

## Governance and Review Requirements

- Accountable owner：`backend`；Media read 遵守现有 `BE-MEDIA-STORAGE` security/retention boundary，使用 backend TDD 与 `karpathy-guidelines`。

- 安全测试必须覆盖 cross-user 与 wrong session，不能只测 happy path。
