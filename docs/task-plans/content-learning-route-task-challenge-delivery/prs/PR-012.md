# PR-012: 全链验收与交付记录

## Objective

新增定向 integration test，验证 Course detail → 五阶段路线 → exact Course challenge → opener/history → authenticated audio playback/失败恢复，
并在唯一一次全量 Maven/Flutter 回归后完成 traceability 终检、development status、implementation report 与独立质量/QA/治理检查。

## Included Scope

- 新增单条端到端 integration test，使用 test fixtures 覆盖 exact Course/version/binding、路线状态、challenge context、opener、history、audio success/404/503 recovery。
- 运行一次全量 Backend/Flutter suites，以及 API、AI、Story、document、diff validators。
- 终检 Story→FR→Contract→TC→implementation lineage，更新 development status 与 implementation report。
- 记录 exact branch/HEAD 或 scoped candidate identity、命令、passed/failed/skipped、baseline failure、剩余风险和 rollback context。
- 执行独立 code quality、QA 和适用 product-object/software-architecture governance review。

## Excluded Scope

- 新产品功能、生产 seed、部署、生产 migration、远程 PR、提交/推送或无授权 release。
- 静默修复前序实现缺陷；发现缺陷时回到 owning PR 或先修订本卡具体路径/测试并重新审批。

## Context Budget

- 上限：16k tokens。
- 读取范围限于最终 approved VS/FR/Contracts/TC、PR-007–011 evidence、integration fixture seams 和交付报告模板；不重新加载全部实现文件，除非失败定位需要且先记录原因。
- 任何实现修复都会改变 Included Scope/Allowed Paths，必须先修订并重新审批；预估超限时拆出缺陷修复卡，不吞入本验收卡。

## Acceptance Criteria

- integration test 覆盖 route 五阶段、仅 01 可进入、exact context、单 opener、历史 role/audio、404/503 可恢复和返回路线。
- 全量 `mvn test`、`flutter analyze`、`flutter test` 各运行一次并记录完整结果；此前各 PR 不重复运行这些全量套件。
- 既有范围外失败有 exact baseline、可重复命令与影响判定；未修复或无明确例外时计划保持未完成。
- traceability 无缺口；development status 与 implementation report 不夸大生产部署/迁移/发布状态。
- 独立 review 无未关闭 required finding；十二张卡均已分别验收后才可完成总任务。
