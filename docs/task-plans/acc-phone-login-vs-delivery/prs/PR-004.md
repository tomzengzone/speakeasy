# PR-004: WP-4 虚拟运营商号段风险接入（VS-ACC-001-13）

## Objective

交付虚拟运营商手机号段的风险识别与风险因子传递，不在基础手机号校验阶段直接拒绝。

## Included Scope

- `VS-ACC-001-13`：识别 `170`、`171`、`165`、`167` 等虚拟运营商号段。
- 合法虚拟运营商手机号继续基础验证码流程。
- 将命中结果作为风险因子交给既有 `US-110` 后端风控策略。
- 根据风控返回结果决定是否触发额外验证；本 WP 不定义策略内容。

## Excluded Scope

虚拟运营商号段清单的产品政策、`US-110` 风控规则、额外验证方式本身，以及普通手机号主链路。

## Allowed Paths

- `lib/services/auth_service.dart`
- `lib/models/auth_models.dart`
- `backend/src/main/java/com/speakeasy/api/AuthController.java`
- `backend/src/main/java/com/speakeasy/identity/**`
- 既有风险服务/策略接入路径，仅限传递与消费本风险因子所需文件
- 对应的 `test/**` 与 `backend/src/test/**` 测试文件
- API 边界确有变化时所需的既有契约及生成代码路径

## Acceptance Criteria

- 合法的虚拟运营商手机号不会仅因号段而被客户端或认证服务直接拒绝。
- 命中号段时，后端风控收到明确且可审计的风险因子。
- 非虚拟运营商手机号不被错误标记为该风险因子。
- 是否触发额外验证完全服从既有风控策略结果。
- 风控依赖不可用时采用正式契约规定的失败行为，不得静默绕过风险判断。

## Verification Commands

- `flutter test test/services/auth_service_test.dart`
- `mvn -f backend/pom.xml -Dtest=AuthControllerTest,AuthServiceTest test`
- 风控接入新增或既有定向测试
- `flutter analyze`

实现完成后需要独立代码质量审查。
