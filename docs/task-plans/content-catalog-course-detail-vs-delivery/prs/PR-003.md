# PR-003: API Contract/OpenAPI/generated Dart/Contract-TC/Traceability

## Objective

把已接受的 Course 领域事实转化为前后端唯一 API 边界、machine-readable OpenAPI/generated Dart、
稳定 Contract-TC 和派生 TRACEABILITY，使后端与 Flutter 可以针对同一版本固定协议独立实现。

## Included Scope

- 保留并修正 `GET /scenarios` 作为主题集合；新增
  `GET /scenarios/{scenario_id}/courses` 和
  `GET /courses/{course_id}/versions/{course_version_id}`。
- 定义 published/visible 过滤、零课程主题、空集合、非法/不存在 course/version、版本不匹配、
  entitlement/access 和 typed error 语义；不得用相邻等级、其他课程或最新版本静默替换。
- 课程摘要固定包含 `course_id`、`course_version_id`、`title_en`、`summary_zh`、`level_code`；
  详情增加 `typical_duration: {value, unit}` 和可空 `background_asset_ref`。
- OpenAPI schema、examples、operation traceability、generated Dart path/type registry、hash 与 drift manifest。
- 为 Course catalog/detail、版本固定、binding 一致性、seed/migration、可见性/空错语义设计 Contract-TC；
  保持既有 CEFR Contract-TC 回归覆盖。
- 更新 TEST_CASE_CATALOG 的直接 contract edge，并由 traceability owner 重建 001/002 的派生投影。

## Excluded Scope

- Spring controller/service/repository、Flyway migration、seed 执行、Flutter UI 或 runtime 实现。
- 003–012 draft endpoint、CMS/authoring API、课程阶段/训练/AI/媒体/评分 API。
- 修改 Story/VS/FR 或把 TRACEABILITY 当作直接关系事实源。

- `docs/task-plans/content-catalog-course-detail-vs-delivery/**`，仅计划状态、checkpoint 和证据

## Acceptance Criteria

- API Contract 逐项承接 `FR-CONTENT-001/002`：完整 published/visible 集合、零课程主题、空错区分、
  strict CEFR、Course ID + version 固定详情、必备字段、正值时长、可选背景和不替代语义。
- `200 courses: []` 只表示真实零课程；不存在、未发布或不可见资源使用不泄露信息的 `404`，
  查询故障使用可重试的 typed `503`。响应包含 `schema_version`、`request_id`、确定性排序及私有 ETag。
- List/detail response 使用稳定 `course_id`、`course_version_id` 和 binding reference；课程卡片携带的 version
  可以原样用于详情读取，服务端不得静默提升到其他版本。
- OpenAPI paths、schemas、examples、4XX 和 x-traceability 完整；generated Dart 与 OpenAPI hash/path/type
  一致，无手写未登记 `/cards` 或 legacy Course level。
- 新增 Contract-TC 各自只有一个 `source_contract_id` direct edge、稳定 selector、script_path 和可执行命令；
  现有 FR-TC/VS-TC 不被测试意图替代。
- TRACEABILITY 仅从 Story/FR/Engineering Contract/TC owning sources 重建，无悬空 ID 或反向 authority。
