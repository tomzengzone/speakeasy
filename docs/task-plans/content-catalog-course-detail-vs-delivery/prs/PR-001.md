# PR-001: Content 001–012 Architecture Coverage Matrix、SWC/数据流/ADR

## Objective

以 approved Content 001/002 为唯一 normative 产品输入，完成 Content 001–012 的一次性架构全景扫描，
并为 003–012 建立逐 US Architecture Coverage Matrix，锁定最小生产 Course SWC、扩展缝、数据流、
兼容 non-goal、迁移和回滚方向。后续已批准 Slice 默认从矩阵执行局部 architecture-impact check，
仅命中明确触发条件时重新开启整体架构或 ADR 决策。

## Included Scope

- 把 001/002 映射为当前必须支持的主题目录、课程摘要、稳定版本详情、空/错恢复和可见性读取流。
- 在 `docs/architecture/software_component_architecture.md` 建立 Architecture Coverage Matrix，
  `US-CONTENT-003` 至 `US-CONTENT-012` 每个 US 恰好一行，不以分组行替代单项覆盖。
- 每行必须包含：Story/当前 authority、预期 owning SWC、与 Course/CourseVersion 的关系、消费与产生的
  稳定引用类别、不得放入 Course 的运行时事实、未来需要新增或变更的 Engineering Contract 类型、
  当前架构适配结论，以及重新触发 ADR/整体架构分析的具体条件。
- 在 `module_boundary.md` 和 `swc_catalog.md` 固化矩阵使用的所有权、复用和 forbidden-duplicate 规则；
  在 ADR 中固化后续 Slice 先做矩阵 impact check、命中触发条件才重开架构决策的演进规则。
- 定义 Course catalog SWC 与既有 Scenario/Content、Backend、Flutter、OpenAPI、entitlement、
  observability 的责任边界、复用决策、禁止重复和跨层数据流。
- 明确 `Course != Scenario`；CourseVersion 后续必须经 CourseContentBinding 绑定
  ScenarioVersion + ScenarioLevel；ScenarioLevel 保留且不删除、不重命名。
- 用 ADR 记录为何新增最小 Course aggregate 而不复用/重命名 ScenarioLevel，以及 additive migration、
  灰度启用、关闭新读取路径和兼容应用版本回退方向。

## Excluded Scope

- 修改 Story/VS/FR、批准 003–012、定义其具体阶段/运行时/AI/媒体/评分行为。
- 从 draft 推导具体实体字段、API path/payload、状态机、持久化表、供应商选择或验收承诺。
- 创建领域实体细节、API schema、OpenAPI、Screen Spec、migration、测试或应用代码。
- 通用 CMS、课程生产工作流、六级内容补齐、Scenario/ScenarioLevel 替换或 legacy 双轨兼容。

## Acceptance Criteria

- 架构输入清单明确标注 001/002 normative，003–012 draft/compatibility/non-goal；没有 draft 行为被写成
  当前 endpoint、字段、状态机、供应商选择或交付承诺。
- Architecture Coverage Matrix 恰有 10 个可追踪行，逐项覆盖 `US-CONTENT-003`、`004`、`005`、
  `006`、`007`、`008`、`009`、`010`、`011`、`012`，且每行八类信息全部填写，不以 “TBD” 通过验收。
- 每个 owning SWC 使用 `swc_catalog.md` 中的稳定 SWC ID；若分析确认必须新增 SWC，须在本 PR 同步登记
  其单一责任、上下游和禁止重复边界，不得只在矩阵中创造未登记名称。
- 每行明确区分 Course/CourseVersion 持有的 authored/versioned reference 与 Learning、Practice、Training、
  AI Runtime、Media 等边界持有的 progress、session、turn、recording、transcript、score 或 evidence 事实。
- 每行列出后续批准该 Slice 时需要进入的适用 Artifact 类型，但不得提前写出具体 Contract 内容。
- 每行给出 `fits-baseline` 或 `architecture-review-required` 结论及可判定触发条件；至少覆盖稳定 Course/version
  身份改变、事实所有权跨 SWC 移动、新跨 SWC 事务、新 provider/storage/security 边界、以及与既有复用规则冲突。
- ADR 明确：后续 Slice 未命中矩阵触发条件时只做局部 impact check 和对应 Contract 增量；命中时才重开
  整体架构或新 ADR。矩阵不因其来源 Story 为 draft 而成为实现授权。
- Course catalog 的 SWC 责任、上下游、复用、禁止重复、读取数据流和失败边界可被后续领域/API/实现消费。
- ADR 明确 Course、Scenario、ScenarioVersion、ScenarioLevel 的身份差异；禁止把 ScenarioLevel 改名或
  假装成 Course，并要求 CourseVersion 绑定一个匹配的 ScenarioVersion 和 ScenarioLevel。
- 数据流覆盖主题集合、主题下课程摘要、按 Course ID + version 获取详情、可见性判定、真实空集合、
  typed failure、请求/观测标识和回滚路径。
- 架构不创建通用 CMS，也不要求 A1/C1/C2 存在课程；六条 seed 是本次唯一内容库存输入。
