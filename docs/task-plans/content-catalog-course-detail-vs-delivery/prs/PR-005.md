# PR-005: Spring/Flyway Course schema 与后端读取实现

## Objective

按已批准的 `VS-CONTENT-001-1`、`VS-CONTENT-002-1`、适用 FR 以及已接受的架构、领域、API
和 UX 契约，实现 Spring/JPA/Flyway Course schema、持久化与只读查询边界，为两个 Flutter VS
提供稳定、版本固定且可验证的 production backend。生产 migration 只建立 schema、constraints 与
indexes，不写入 Course、CourseVersion 或 CourseContentBinding 内容；本 PR 不新增或改写产品行为。

## Included Scope

- Course、CourseVersion、CourseContentBinding JPA entity/repository/service/controller 与授权/可见查询。
- 在既有 `OnboardingContentController` 内最小调整 `GET /scenarios` 的现有 handler，补齐 approved
  全集、request ID 与 private cache contract；不得另建一个重叠的 `/scenarios` handler。
- 只新增 Flyway migration，建立表、索引、unique/check/FK；不得插入 Course、CourseVersion 或
  CourseContentBinding 内容。
- 主题全集、主题下 published/visible Course summaries、按 Course ID + version 详情、真实空集合和 typed failure。
- migration、binding、controller/service、CEFR/Scenario 非回归与 Contract-TC 实现。
- 六条既有 Course 样例只能由 backend test setup/fixtures 创建和清理，用于确定性测试 oracle；不得进入
  `backend/src/main/resources/**`、runtime 配置或任何生产发布内容。
- 按 PR-001 接受方案实现必要的观测字段和可关闭新读取路径的 rollout/rollback control。

## Excluded Scope

- 改写既有已执行 migration、删除/重命名 ScenarioLevel、legacy alias/dual-read、通用 CMS 或内容写 API。
- Flutter、Roadmap、Screen Spec、Story/FR/TC/Traceability 修改，或 003–012 runtime/AI/media 实现。
- 任何正式 Course 内容创作、生产默认库存或发布内容；尤其不虚构 A1/C1/C2 内容。
- 在 production migration、main resources、runtime 配置或发布包中写入六条测试样例或其他 Course 内容。

## Acceptance Criteria

- Migration 在现有 schema 上一次成功且重复启动安全；既有 migration 未改写，Scenario/ScenarioVersion/
  ScenarioLevel ID 和 CEFR 数据保持不变。
- 生产 migration 只创建 Course schema、constraints 与 indexes；执行后不产生任何 Course、CourseVersion
  或 CourseContentBinding 内容记录。migration 不包含用于测试样例的 content `INSERT`/upsert/copy。
- 六条既有 Course 样例只存在于 backend test setup/fixtures，并由测试独立创建和清理；不得被 main
  resources、runtime 配置或生产发布引用，也不构成产品内容事实。
- 主题与课程 list 恰好返回 published/visible 记录，零课程主题返回空列表；非法/隐藏/不存在/版本不匹配
  返回契约 typed result，不 fallback 到其他课程、版本或等级。
- Course detail 固定读取请求版本并返回所有必备字段；null background 不阻断。
- Content 只消费 Commerce 提供的 typed visibility decision，不解析 raw entitlement JSON/flag key；同一请求使用
  一致的 opaque visibility revision，并把它纳入三个读取操作的 ETag。
- request ID 在共享 filter 中只解析或生成一次；success/304、security/exception error body、
  `X-Request-Id` 响应头与 Course 脱敏观测使用同一安全值。
- 外部 privacy-safe `404` 保持收敛，内部仍区分 theme/course/version missing、unpublished、invisible 与
  binding/dependency outcome；Course slug 必须以小写 trim 后 canonical form 持久化且标准化后唯一。
- Contract-TC、migration、controller/service 和现有 CEFR/Scenario 回归通过；日志/指标不泄露敏感数据。
- canonical Course tests 必须以 test-only fixtures/oracles 证明真实零 Course、draft/superseded/hidden、
  binding 整体失败、list/detail 一致性、visibility revision cache invalidation 与 route-off 隔离；六条样例
  如被使用只能作为测试 fixture，不得把“精确六条生产 inventory”作为 oracle；不得只证明方法执行。
