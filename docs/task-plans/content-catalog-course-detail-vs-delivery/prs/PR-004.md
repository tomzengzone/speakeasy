# PR-004: Screen Spec/User Flow/UX 状态契约

## Objective

基于 accepted Course API 定义 `VS-CONTENT-001-1` 与 `VS-CONTENT-002-1` 的实现就绪屏幕、
跨屏流程、状态转换、可访问性、稳定 selector 和恢复语义，不引入 003–012 的课程学习行为。

## Included Scope

- 内容资产入口、主题集合、主题选择、课程摘要集合、课程卡片和版本固定课程详情 header。
- loading、loaded、zero-course、empty catalog、partial/failed load、retry、stale/missing version、
  background missing、unauthorized/hidden 等可见状态及其 source of truth/next state。
- 获取失败保留已知主题/课程浏览上下文；真实空集合与失败文案/控件明确区分。
- 本轮唯一 Course 详情入口为目录课程卡片；卡片携带 `course_id + course_version_id`，
  详情不得重新选择 latest。既有 ExpressionCard/lesson 页面不视为 Course 入口。
- 英文标题、中文简介、CEFR、典型完成时长及单位、可选背景的布局、可读性和无障碍要求。
- stable selectors 与既有 `TC-FR-CONTENT-001/002`、`TC-VS-CONTENT-001-1/002-1` 对齐。

## Excluded Scope

- 课程路线/阶段、开始学习、任务挑战、精讲、词汇/表达详情、对话播放、跟读/评分界面。
- 修改 API/领域/Story/FR/TC 行为，或用 UX 文案补写未批准产品语义。
- Flutter 实现、图片生成、视觉品牌重设计、运营推荐或 CMS 管理界面。

## Allowed Paths

- `docs/ux/screen_spec.md`
- `docs/ux/user_flow.md`
- `docs/ux/usability_checklist.md`
- `docs/task-plans/content-catalog-course-detail-vs-delivery/**`，仅计划状态、checkpoint 和证据

## Acceptance Criteria

- Screen Spec 为 catalog/theme/course-list/course-detail 定义组件、状态、主要动作、source of truth、
  next states、API 依赖、失败恢复、accessibility 和 stable selectors。
- 已发布零课程主题仍可选择并展示真实空状态；catalog/course fetch failure 显示恢复入口且不清空已知上下文。
- Course summary 可定位英文标题、中文简介、唯一 CEFR 和固定版本引用；详情 header 展示英文标题、
  中文简介、CEFR、正值时长及单位，背景为 null 时使用无误导的占位且其他信息正常。
- 目录课程卡片到详情的 flow 保持原 `course_id + course_version_id`；missing/stale version 不展示其他版本。
- 003–012 只出现在明确 non-goal/后续入口边界，不出现可执行阶段、训练、AI、媒体或评分状态。
