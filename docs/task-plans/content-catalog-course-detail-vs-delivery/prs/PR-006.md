# PR-006: Flutter 主题/课程目录（VS-CONTENT-001-1）

## Objective

独立交付 `VS-CONTENT-001-1` / `FR-CONTENT-001`：学习者浏览全部 published/visible 主题，
选择主题查看全部 Course summaries，并能区分真实空状态和可恢复获取失败。

## Included Scope

- 补齐现有 generated Dart boundary 对 `ScenarioListResponse`、`ScenarioSummary`、`AccessState`、
  `CourseListResponse`、`CourseSummary` 与 `CourseContentBindingRef` 的 typed DTO/strict decoder；
  `FE-API-CLIENT` 暴露 typed 主题与课程读取接口，`FE-CONTENT` 只消费该接口并拥有 UI orchestration/state。
- 内容资产入口、主题列表/选择、课程摘要卡片；不得在 `lib/features/content/**` 新建 DTO、HTTP client、
  repository、cache 或 version resolver。
- 英文标题、中文简介、唯一 CEFR、`course_id + course_version` 显示/导航数据。
- loading、zero-course、empty catalog、failure、retry、已知上下文保留和 entitlement/visibility 呈现。
- `401` 提供既有重新认证路径，privacy-safe `404` 清除 learner-specific body 且禁用 retry/refresh 探测。
- `TC-FR-CONTENT-001`、`TC-VS-CONTENT-001-1`、generated DTO/API adapter、production wiring 与 widget regression。
- 将 Windows desktop 明确记录为非产品发布、验收和 Gate 目标；退役与现有 AppRoot widget-integration
  重复、且需要 device/desktop build 的 Content integration test，把 canonical VS-TC 指向可由 Ubuntu CI
  普通 Flutter runner 执行的生产 AppRoot/Home/Content 闭环。
- 明确 OpenAPI 只能经受控 API Contract workflow 变更；PR-006 不建设全量 209-schema generator，但所有
  Flutter 实际消费的 catalog/error DTO 仍必须可重复生成并通过定向 schema signature/drift 校验。

## Excluded Scope

- Course detail、开始学习、003–012 行为、Flutter 本地 Course 事实源或离线 CMS。
- 修改 OpenAPI 语义、Backend、migration、seed、Engineering Contract、Story/FR 行为，或生成
  PR-007 才需要的 Course detail UI/adapter。
- 批量删除其他具有独立系统价值的 integration tests，或新增 Windows/desktop CI、打包与插件工具链。
- 复用未接线 `/cards`，或把 legacy `ExpressionCardData` 当作 Course DTO。

## Acceptance Criteria

- “全部”主题集合和选中主题课程集合恰好呈现 API 返回的 published/visible 项，不客户端截断或虚构。
- 已发布零课程主题仍显示并呈现真实空状态；获取失败不显示为空集合，保留已知主题/选择和 retry。
- 每张 Course summary 可定位非空英文标题、非空中文简介、唯一合法 CEFR、course ID 和固定 version。
- A1/C1/C2 无 Course 时不 fallback；legacy L1/L2/L3 被 strict reader 拒绝。
- `FE-CONTENT` 不解析 raw JSON、不重定义 DTO/错误语义、不创建 Course repository/client/cache/version resolver；
  catalog 数据只来自 `FE-API-CLIENT` 返回的 generated DTO。
- `401` 清除旧 learner-specific body 并暴露既有重新认证动作；`404` 只显示“内容暂不可用”，
  不保留旧 body，也不提供 retry、refresh 或其他资源探测动作。
- VS 测试从生产首页入口经过 AppRoot 的 typed API wiring 进入主题和课程列表，而不是直接 pump 页面并绕过接线。
- `TC-VS-CONTENT-001-1` 以 `widget-integration` 运行现有 AppRoot/Home/Content production wiring；不得再要求
  Windows desktop build、`-d windows`、CMake、NuGet 或 Windows plugin smoke 作为该 VS 或后续产品 Gate。
- Windows 主机仍可执行 platform-neutral Dart/Flutter/Python 测试；“Windows host”不得等同于“Windows 产品目标”。
- OpenAPI 不允许绕过 `api-contract-generate`/owner/Gate 直接改动；受控 workflow 变更后，实际消费 schema 的
  generated DTO、schema signature、hash 与 typed decoder test 必须同步，不能以“无人手改”为由取消 drift gate。
- canonical FR-TC 和 VS-TC 通过，且现有 Scenario/首页主要路径无回归。
